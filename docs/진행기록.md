## 4단계 — 2.5.4 관통

```
정책 docx ──① 수용(매직바이트·ClamAV·SHA-256)──④ 정규화(조·항·호 Clause)──⑤ 문서 관측(규칙 추출 [+Ollama, 인용 검증])
AWS 스냅샷 ─① 수용(SHA-256)────────────────────⑤ 기술 관측(정책·사용자·Cognito)
                                                     │
                       ⑥ Q/C/P (품질: 인용 원문 일치, 수집 신선도 7/30일, 검역 상태 · 범위: 문서 분모, 계정별 수집)
                                                     │
                       ⑦ 규칙 실행기(AR YAML 해석) → 판정 함수(D05 순서) → ⑧ 귀속(위반 1건 = 결함 사실 1건, 대표 기준 1개)
                                                     │
                       ⑨ 검토(승인·반려·추가자료, 기록은 추가만 가능) → ⑩ 보고서(xlsx·md)
```

**설계상 중요한 선택**
- **규칙 = AR YAML + 해석기.** AR마다 파이썬 함수를 쓰지 않고, 테스트 유형별 의미를 `rules/evaluator.py` 한 곳에 둡니다. 결과에는 요구사항 파일 해시와 해석기 버전이 남습니다.
- **판정 순서.** 직접 위반은 Coverage 검사보다 먼저 봅니다. 그래서 stg 계정 수집이 실패해도 prod에서 확인된 위반은 결함 후보로 나옵니다 (테스트 `test_violation_beats_partial_coverage`).
- **부재 판단의 조건.** "규칙이 없다"는 결함은 문서 분모(scope.yaml의 `policy_documents`)가 다 정규화됐을 때만 냅니다.
- **LLM은 보조 역할.** 기본은 정규식 추출(결정적)입니다. Ollama 결과는 인용이 원문 Clause에 글자 그대로 있고 숫자 값이 인용 안에 있을 때만 채택합니다. 규칙 추출과 값이 다르면 충돌로 처리하고, 그 AR은 결함도 적합도 아닌 판정이 됩니다.
- **하나의 사실은 1건으로.** IAM 정책이 아예 없는 계정은 비교 항목이 7개여도 결함 1건으로 셉니다.
- **결정성.** 같은 입력을 10번 돌려도 결과 해시가 같습니다 (실행 시각은 해시에서 제외).

**정답지 대비 결과**: AR 5개 모두 판정 상태와 결함 대상이 일치합니다 (`gapcheck check`).

## 알려진 한계

1. **AR-03 탐지 한계.** 관리자가 `UpdateLoginProfile`로 비밀번호를 재발급하면 로그인 프로필 생성 시각이 바뀌지 않습니다. 그래서 재발급 후 변경하지 않은 경우를 놓칠 수 있습니다. CloudTrail의 `UpdateLoginProfile` 이벤트를 수집하면 보완됩니다.
2. **AR-05 화면 증적.** 화면 캡처는 자동으로 판독하지 않고 "사람 검토 필요"로 남깁니다. Cognito를 쓰지 않는 서비스는 결과가 부분(미확인)으로 나옵니다.
3. **규칙 추출기 범위.** 정규식은 A사 문서의 표현을 기준으로 만들었습니다. "3종류 이상 조합 시 8자리, 2종류 조합 시 10자리"처럼 조건이 붙은 규칙은 아직 해석하지 못합니다. 다른 문서 양식에서는 Ollama 보조와 패턴 추가가 필요합니다.
4. **검증하지 못한 부분.**
   - Terraform 코드는 작성 환경에 Terraform이 없어 `validate`를 돌리지 못했습니다.
   - docker-compose 전체 기동과 실제 AWS 수집은 Mac에서 처음 확인하게 됩니다.
   - live 수집기는 Stubber 테스트만 거쳤습니다.
5. **자동 점검 범위.** 101개 인증기준 중 자동 점검은 7개(2.2.5, 2.5.1~2.5.6)입니다. 나머지 94개는 담당자 판단으로 채웁니다.
6. **영업일 계산.** 퇴직자 회수 기한의 영업일은 주말만 빼고 공휴일은 반영하지 않습니다.
7. **관리자 권한 판정.** AdministratorAccess, IAMFullAccess, 모든 작업·모든 자원 허용 정책만 관리자로 봅니다. 역할(Role) 전환으로 얻는 권한과 권한 경계(Permission Boundary)는 아직 보지 않습니다.

## 변경 기록

### 2026-11-02 — 원본 저장소 이미지 교체
- **문제:** Mac에서 처음 기동할 때 `pull access denied for minio/minio` 오류가 났습니다. MinIO가 2026-09-11 Docker Hub에서 공식 이미지를 삭제했고, quay.io도 익명 다운로드를 막았습니다.
- **조치:** `cgr.dev/chainguard/minio:latest`로 교체했습니다. 이 이미지는 uid 65532로 실행되므로, 볼륨 소유자를 맞추는 `minio-init`(busybox) 단계를 추가했습니다. 포트는 127.0.0.1에만 열었습니다.
- **남은 결정:** Chainguard 무료 플랜은 latest 태그만 제공합니다. 재현성이 필요해지면 digest로 고정합니다. 장기적으로는 RustFS 같은 S3 호환 대안을 검토합니다. 코드는 S3 API만 쓰므로 교체 비용이 작고, AWS 배포에서는 S3를 씁니다.
